# 性能记录

## 2026 年 11 月实测

设备为 Mac M4 Pro 与 Galaxy S25 Ultra，模型为 v2Pro。每组 A/B 使用相同文本和参考音，
并固定采样设置。量化或后端属于实验变量时在该组注明。TTFA 从提交文本计到首段 PCM 回调，
RTF 为合成耗时除以成品音频时长。模拟播放假设收到首包后立即播放，根据后续 PCM 的到达时间
计算最小余量和断供。扬声器实测使用 Android AAudio 的呈现时间戳和欠载计数。

### CPU 句内流式

两端使用同一套量化 ONNX、参考音和种子 42，热机 CPU 合成。S25 Ultra 使用 4 线程共享
ORT 池。Hybrid（Adaptive）从 8 token 起步，每类测 5 条文本。Mac 每条两轮，S25 Ultra
每条一轮。两台设备的这些测试均无模拟断供。

| 输入 | Mac M4 Pro TTFA / RTF | S25 Ultra TTFA / RTF |
| --- | ---: | ---: |
| 独立短句 | 140 ms / 0.094 | 404 ms / 0.241 |
| 无逗号长句 | 158 ms / 0.106 | 356 ms / 0.255 |
| 有自然停顿的长句 | 156 ms / 0.113 | 382 ms / 0.293 |
| 多句正文 | 240 ms / 0.112 | 451 ms / 0.255 |
| 短开头接长正文 | 181 ms / 0.113 | 336 ms / 0.312 |
| 25 条平均 | 175 ms / 0.108 | 386 ms / 0.271 |

8 token 起步时，Mac 最小播放余量为 262 ms，S25 Ultra 为 198 ms。Mac 以 16 token
起步测同一批文本，平均 TTFA 为 190 ms、RTF 为 0.104，最小播放余量为 504 ms。

### S25 Ultra 超长语音播放

独立 CPU demo 使用 Hybrid（Adaptive）处理一次提交的四段自然句。首包 465 ms，
合成 72.04 秒音频耗时 15.76 秒，RTF 为 0.219，模拟断供 0 次。末段回转写检出完整结尾。

独立 CPU 基准使用 Hybrid（Adaptive），将 PCM 写入 AAudio 内置扬声器路径。
556 字符的单句由前处理拆成两个约 280 字的模型段，实际播放了 104.44 秒。
回转写发现重复和漏读，且未检出结尾。

## Qualcomm QNN pipeline

S25 Ultra 使用 ORT 1.30.0、QAIRT 2.51.0 和 burst。VITS 生成器固定 128 帧，
权重 8 位、激活 16 位。HTP 生成器计时包含提交 `z`、`ge` 和取回 PCM。

- **上采样。** 由打包卷积改用 `ConvTranspose` 后，暖态生成器运行中位数从
  152.47 降到 137.38 ms，四轮配对中位节省 9.9%。两者均为单个 HTP 子图。
  同一输入的 PCM RMS 差为 0.0000529，峰值差为 0.000427。转置卷积图即时编译加载
  约 6.93 秒，加载 `EPContext` 的中位时间约 295 ms。
- **固定窗口拼接。** 同一组 `z`、`ge` 下，6 条、合计约 51.32 秒的样本，
  CPU 分块和 CPU 整段的 PCM 逐样本一致。HTP 分块对 CPU W8A16 整段的 RMS 差为
  0.00110、SNR 为 35.9 dB。换一组拼接位置后，HTP 分块输出逐样本一致。
- **跨句并行。** 6 条中长句、合计约 53.12 秒音频，CPU T2S 与 HTP VITS
  串行合成的中位耗时为 12.33 秒，跨句并行为 10.04 秒。三轮配对中位节省 18.6%，
  语义 token 和 PCM 全部一致。早期启用 QNN 的应用试听三次中位值为 14.38 秒音频、2.80 秒合成、
  RTF 0.195，从请求到开始播放为 2.81 秒。应用使用 CPU INT4 共享 KV 和保留末端
  `Gather` 的 HTP 图。

以下两项为单独的图实验。

| 实验 | S25 Ultra 结果 | 输出与子图 |
| --- | --- | --- |
| HTP 输出端合并 Gather／QDQ | 五轮配对的生成器中位节省 0.058 ms，基线约 137 ms | 浮点输出端 `Reshape` 版本维持单个 HTP 子图，9 组 PCM 逐样本一致。UINT16 折叠版本有两个节点落在 CPU |
| T2S NPU FP16 Decode-1(512) 对照 CPU INT4 | 逐步复制 KV 时整批慢 25.7%。共享 KV 后，解码 4.39 → 3.84 ms/token，6 条中长句合成 11.39 → 10.63 秒，配对中位节省 6.7% | 单个 HTP 子图，3/6 条达到容量后切回 CPU。相同解码状态下 Top-1 一致 928/1036 步，独立采样的 18 对语义 token 和 PCM 均有差异 |

共享 KV 的 NPU 路径在后续 profiling 中约为 3.29 ms/token，其中约 2.99 ms
在 HTP 计算，算子周期主要花在注意力与投影。

### HTP 窗口逐块交付

S25 Ultra 独立 CLI 测同一批 6 条中长文本，共 66.82 秒音频。原 QNN 和逐窗口 QNN
使用同一份 W8A16 生成器与设备 EPContext。三组共享 T2S、参考音和采样 seed 42，CPU
Adaptive 从 16 token 起步。每条预热 1 次，再测 3 次。表格为每条热态中位数，汇总行对
6 条中位数取平均。断供按 PCM 块的到达时间与预计播放余量计算。

| 中句 1 | 6.42 s | 1,334 ms / 0.208 | 1,038 ms / 0.211 | 364 ms / 0.241 |
| 中句 2 | 7.02 s | 1,456 ms / 0.207 | 1,111 ms / 0.203 | 401 ms / 0.237 |
| 中句 3 | 7.74 s | 1,680 ms / 0.217 | 1,193 ms / 0.216 | 435 ms / 0.235 |
| 长句 1 | 13.02 s | 2,872 ms / 0.221 | 1,965 ms / 0.214 | 492 ms / 0.226 |
| 长句 2 | 19.26 s | 4,394 ms / 0.228 | 3,004 ms / 0.221 | 606 ms / 0.258 |
| 双句 | 13.36 s | 1,980 ms / 0.176 | 1,532 ms / 0.175 | 461 ms / 0.227 |
| 平均 | | 2,286 ms / 0.210 | 1,640 ms / 0.207 | 460 ms / 0.237 |

逐窗口 QNN 的平均首包提早 646 ms（28.2%）。三组各 18 轮热态推理的模拟断供均为 0 次。
QNN 首包仍需等待首句的 CPU T2S 和 VITS 前缀完成。
PCM 对照在同一台设备上复跑两版 QNN。临时前缀图固定 `RandomNormalLike` 的 seed，
两版共用同一个参考 `ge`、W8A16 生成器和 EPContext。6 对 WAV 共 2,138,240 个 float32
PCM 样本逐位一致，包含窗缝和句末静音。上表计时使用原始前缀图。
